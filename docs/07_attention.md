## 1. Attention

Transformer の原論文のタイトルは "Attention Is All You Need"（Vaswani et al., 2017）であり、Attention こそが Transformer の中核です。従来のモデルで使われていた再帰構造や畳み込みを排し、Attention だけで系列全体の依存関係を捉えられることを示しました。

## 2. Q, K, V（Query, Key, Value）

次の単語を予測するには、現在のトークンだけでなく文脈中の他のトークンの情報も必要です。どのトークンがどれだけ関連するかを判断し、必要な情報を集めてくる仕組みが Attention です。

### 人工的な例で見る Attention

Attention の考え方を、`a commercial bank`（商業銀行）と `a grassy bank`（草に覆われた土手）という小さな人工例で見てみます。どちらも形容詞が名詞 `bank` を修飾しており、`bank` が形容詞の情報を取り込むと、文脈に応じた意味を表現できます。

説明のため、単語ごとに 1 トークンとして、入力ベクトルの軸を `[名詞, 形容詞, 金融, 地形]` と決めます。

| トークン | 入力ベクトル |
|---|---|
| a | `[0, 0, 0, 0]` |
| commercial | `[0, 1, 1, 0]` |
| grassy | `[0, 1, 0, 1]` |
| bank | `[1, 0, 0, 0]` |

各トークンの入力ベクトルから、同じルールで Q・K・V を作ります。この関連するトークンを探して情報を集める処理は、検索の比喩によって 3 つの役割が割り当てられます。

- **Q (Query)**: 「何を探しているか」。ここでは入力ベクトルと重み `[3, 0, 0, 0]` の内積（名詞成分の 3 倍）で作り、名詞が修飾語を探すようにする
- **K (Key)**: 「何を手がかりに見つけてもらうか」。ここでは入力ベクトルと重み `[0, 1, 0, 0]` の内積（形容詞成分）で作り、形容詞が検索に応じるようにする
- **V (Value)**: 「実際に渡す情報」。ここでは `[金融成分, 地形成分]` とする

例えば `bank` の入力 `[1, 0, 0, 0]` と Q 用の重み `[3, 0, 0, 0]` の内積は、`1 × 3 + 0 × 0 + 0 × 0 + 0 × 0 = 3` です。これで `bank` の Q は `[3]`、形容詞の K は `[1]` になります。係数 3 は、注目度の違いを見やすくするために選んだ値です。Q と K の内積が大きいほど注目度が高くなり、そのトークンの V を多く受け取ります。内積の値（スコア）は、Softmax で合計が 1 になるよう調整して、注目度にします。

GPT-2 では**因果マスク**により、自分自身と前にあるトークンだけを参照できます。`bank` が前の形容詞を参照するので、情報は `commercial / grassy → bank` の向きに流れます。逆に、形容詞が後ろの `bank` を参照することはできません。ここでは最後の `bank` に注目するため、3 トークンすべてが参照対象です。

なお、この入力ベクトルと変換ルールは、仕組みを見せるために手で決めたものです。**実際の GPT-2 では、品詞や意味がこのような専用の軸に分かれているわけではありません**。入力の表現と Q・K・V への変換は学習によって得られます。この例では、位置情報や LayerNorm なども省略しています。

```python
# 入力ベクトルの軸: [名詞, 形容詞, 金融, 地形]
toy_embeddings = {
    "a":          [0, 0, 0, 0],
    "commercial": [0, 1, 1, 0],
    "grassy":     [0, 1, 0, 1],
    "bank":       [1, 0, 0, 0],
}

# 出力射影: [金融, 地形] を入力と同じ 4 次元の軸に戻す
toy_w_out = np.array([[0, 0, 1, 0],
                      [0, 0, 0, 1]], dtype=np.float32)

for adjective in ["commercial", "grassy"]:
    toy_tokens = ["a", adjective, "bank"]
    toy_x = np.array([toy_embeddings[t] for t in toy_tokens], dtype=np.float32)

    # 全トークンの Q・K・V を、それぞれの入力から同じルールで作る
    toy_q = 3 * toy_x[:, :1]  # 重み [3, 0, 0, 0] との内積
    toy_k = toy_x[:, 1:2]     # 重み [0, 1, 0, 0] との内積
    toy_v = toy_x[:, 2:]      # 金融・地形成分

    # 最後の bank の Q で、各トークンの K を照合する
    toy_scores = toy_q[-1] @ toy_k.T
    toy_weights = softmax(toy_scores)
    toy_result = toy_weights @ toy_v
    toy_projected = toy_result @ toy_w_out    # 2 次元 → 4 次元（出力射影）
    toy_bank_out = toy_x[-1] + toy_projected  # 元の bank に加算（残差接続）
```

結果です。

```text
  a commercial bank: Q_bank = [3.], scores = [0. 3. 0.], weights = [0.045 0.909 0.045], received = [0.909 0.   ]
    bank: [1. 0. 0. 0.] + [0.    0.    0.909 0.   ] = [1.    0.    0.909 0.   ]
  a grassy bank: Q_bank = [3.], scores = [0. 3. 0.], weights = [0.045 0.909 0.045], received = [0.    0.909]
    bank: [1. 0. 0. 0.] + [0.    0.    0.    0.909] = [1.    0.    0.    0.909]
```

どちらの句でも、`bank` の Q は `[3]`、参照先の K は順に `[0]`・`[1]`・`[0]` なので、スコアは `[0, 3, 0]` です。Softmax によって、形容詞には約 0.909、`a` と `bank` には約 0.045 ずつの注目度が付きます。注目度が 1 にならないのは、Softmax が合計 1 になるよう調整する際に、スコアの低いトークンにもわずかな重みを残すためです。

注目度が同じでも、形容詞の V が異なるので、取り込まれる情報は変わります。`a` と `bank` の V は `[0, 0]` なので、ここでは形容詞の情報だけが注目度に応じて入ります。

| 入力 | 形容詞の V `[金融, 地形]` | bank が受け取る情報 |
|---|---|---|
| a commercial bank | `[1, 0]` | 約 `[0.909, 0]` |
| a grassy bank | `[0, 1]` | 約 `[0, 0.909]` |

次に、この 2 次元の情報 `[f, t]` を、**出力射影**で入力と同じ 4 次元の `[0, 0, f, t]` に戻します。この変換も説明用に手で決めたものです。さらに、元の `bank` の入力ベクトル `[1, 0, 0, 0]` に加算します。これが**残差接続**です（👉[09](09_residual.md)）。

| 入力 | 元の bank | 出力射影した情報 | 加算後の bank |
|---|---|---|---|
| a commercial bank | `[1, 0, 0, 0]` | 約 `[0, 0, 0.909, 0]` | 約 `[1, 0, 0.909, 0]` |
| a grassy bank | `[1, 0, 0, 0]` | 約 `[0, 0, 0, 0.909]` | 約 `[1, 0, 0, 0.909]` |

**入力では同じだった `bank` が、文脈を取り込んだ後は異なるベクトルになりました**。どちらも名詞成分 1 を保ちつつ、`commercial` の場合は金融成分が、`grassy` の場合は地形成分が増えています。そのため、この人工例では「銀行」と「土手」をベクトルの違いとして区別できます。

この結果は、手で設定した人工例での表現です。実際の GPT-2 では、学習済みの出力射影で情報を変換して加算し、さらに MLP や後続のブロックで表現を更新します。

**Q がトークンから作られることと、二つの句で Q が同じであることは矛盾しません**。この例では、同じ `bank` の入力から同じ Q を作っています。実際の GPT-2 でも、最初の層では同じトークンが同じ位置にあれば Q は同じです。それでも参照先の情報が違えば出力は変わり、後続の層では、取り込んだ文脈に応じて `bank` の Q 自体も異なり得ます。

この「Q と K の内積で注目度を決め、その注目度で V を混ぜ合わせて取り出す」処理が **Attention** です。同じトークン列から Q・K・V を作り、各トークンが自分の Q で参照可能なトークンの K を照合して V を集める仕組みを **Self-Attention** と呼びます。GPT-2 の Self-Attention では、因果マスクによって各トークンが参照できる範囲を自分自身と前のトークンに制限します。そのため、**情報はトークンの出現順に前から後ろへ一方向に流れます**。

この例は、名詞が形容詞の情報を集めるという、1 つの**ヘッド**の働きを単純化したものです。実際のモデルでは、ヘッドごとに異なる変換で Q・K・V を作り、複数のヘッドが並行して情報を集め、最後に結果を結合します（**Multi-Head Attention**）。各ヘッドの役割を人が品詞などで指定するわけではなく、その働きも学習によって得られます。

#### 形容詞が後ろにある場合

英語の `a commercial bank` では形容詞が名詞の前にありますが、フランス語の `une banque commerciale` では後ろにあります。どちらも文法上は形容詞が名詞を修飾します。一方、GPT-2 の Attention では、後の語が前の語を参照するため、情報の流れは次のようになります。ここでも説明のため単語単位で考えます。

| 例 | 情報の流れ | 両方の語の情報を取り込む側 |
|---|---|---|
| a commercial bank | commercial → bank | 後の bank（名詞） |
| une banque commerciale | banque → commerciale | 後の commerciale（形容詞） |

**「名詞が意味を集める」という文法的に固定された役割はなく、意味の情報は語が出現する順番に、前から後ろへ伝わります**。名詞と形容詞のどちらが先でも、後の語が前の語の情報を取り込めば、両方の意味を組み合わせられます。どちらの語順でも、情報が集約されるのは後の単語の位置です。先ほどの人工例は、名詞が前の形容詞から情報を集める働きだけを手で設定しましたが、実際のモデルでは、形容詞が前の名詞から情報を集める働きも、学習した Q・K・V の変換によって表現できます。

母語を理解するときの感覚にたとえると、語が現れる順番のまま、それまでの文脈と結び付けながら自然に意味を捉えていくイメージです（学習中の外国語では、母語の語順に合わせて語を並べ替えて理解することもあります）。

フランス語の例で `commerciale` の情報を取り込むのは、`banque` の位置ではなく、`commerciale` の位置です。因果マスクがある限り、全入力をまとめて処理しても、層を重ねても、後の語の情報が前の語の位置に戻ることはありません。それでも、後の語やさらに後続するトークンの位置で両方の情報を取り込めるため、句全体を踏まえて続きを予測できます。

ただし、一般に語順を変えても文の意味やモデルの出力が同じになるということではありません。GPT-2 はトークンの埋め込みに位置ベクトルを足しています（👉[05](05_embedding.md)）。位置ベクトルを足さなければ、同じトークンの初期ベクトルはどの位置でも同じになり、埋め込み自体から位置を区別できません。位置ベクトルを加えることで、その語が何番目に現れたかを Q・K・V にも反映し、語順を踏まえて意味を組み合わせられます。因果マスクは参照できる範囲を制限し、位置ベクトルは各語の位置を明示する役割を担っています。

### Q, K, V への変換

先ほどの例では、入力ベクトルから特定の成分を取り出すという、手で決めたルールで Q・K・V を作りました。これも行列による変換で表せます。実際のモデルでは、各トークンの入力ベクトルから変換して作ります。

- 同じ入力ベクトル `x` に、**別々の 3 つの行列**（$W_Q$・$W_K$・$W_V$）を掛けて、Q・K・V をそれぞれ作る
- 3 つの行列の重みは別々に学習されるため、同じトークンでも「探しもの」「見出し」「中身」として異なる役割を持つベクトルになる
- 実装上は、3 つの行列を横に連結した 1 つの大きな行列で一度に計算し、結果を 3 つに分割する

分割されるのは入力ではなく、**変換後の結果**です。

GPT-2 では各トークンを 768 次元のベクトルで表し、それを 12 個の**ヘッド**に分割します（各ヘッド 64 次元）。ヘッドは、先ほどの例で説明した、Q・K・V を作って情報を集める処理の 1 つ分に相当します。複数のヘッドがそれぞれ異なる観点で文脈を捉えることで、多面的な情報を取り込めます。この仕組みを **Multi-Head Attention** と呼びます。

Q, K, V の生成と出力射影に使う重みとバイアスは safetensors ファイルから読み込まれます。ヘッド数は `config.json` から取得します。GPT-2 では 12 です。

```python
Attention(
    n_head=config["n_head"],                  # 12
    w_qkv=weights["h.0.attn.c_attn.weight"],  # (768, 2304) Q,K,V 結合
    b_qkv=weights["h.0.attn.c_attn.bias"],    # (2304,)
    w_out=weights["h.0.attn.c_proj.weight"],  # (768, 768) 出力射影
    b_out=weights["h.0.attn.c_proj.bias"],    # (768,)
)
```

`c_attn` の重み行列は 768×2304 で、2304 = 768×3（Q, K, V の3つ分）です。1 回の行列積で Q, K, V をまとめて計算してから 3 分割します。この `x @ w_qkv` は成分を混合させる線形変換（768 次元から 2304 次元への写像）です。

3 等分した Q, K, V は、どれも同じ 768 次元です。同じ大きさになるのには理由があります。Q と K は内積でスコアを計算するので、次元数が同じでなければなりません。V は注目度を重みとした加重平均で足し合わせます。ここでは K と同じ次元にして、ヘッドの出力（64 次元）を 12 個並べると、元の 768 次元にちょうど戻るようにしています。

```python
class Attention:
    def __call__(self, x):
        # 768次元の入力に (768, 2304) の重み行列を掛け、Q,K,V を一括計算
        qkv = x @ self.w_qkv + self.b_qkv
        # 2304次元を3等分して Q, K, V（各768次元）に分離
        q, k, v = np.split(qkv, 3, axis=-1)
```

続いて、Q, K, V をヘッドごとに分割します。768 次元を 12 ヘッド × 64 次元に reshape し、transpose でヘッド軸を先頭に移動します。

```python
        # Q, K, V をヘッドに分割: (seq_len, 768) → (12, seq_len, 64)
        def split_heads(tensor):
            tensor = tensor.reshape(seq_len, self.n_head, head_size)
            return tensor.transpose(1, 0, 2)
        q, k, v = map(split_heads, [q, k, v])
```

### 補足：行列積 `@` と内積

`x @ w_qkv` の `@` は**行列積**で、ベクトルどうしの内積そのものではありません。行列積 `A @ B` は、A の各行と B の各列の内積を、すべての組み合わせについて計算して並べる演算です。ここでは `x`（形は `(seq_len, 768)`、1 行が 1 トークン）の各行と、`w_qkv`（形は `(768, 2304)`）の各列との内積を、一括で計算しています。つまり、複数の内積を一括で計算するために、行列積を使っています。

3 次元のベクトルで、イメージを示します。$a_1 = (1, 2, 3)$、$a_2 = (1, 0, 2)$、$b_1 = (2, 0, 1)$、$b_2 = (1, 1, 1)$ とします。まず、横ベクトル（1 行の行列）と縦ベクトル（1 列の行列）の行列積は、内積と同じ計算になります。

$$
\begin{pmatrix} 1 & 2 & 3 \end{pmatrix}
\begin{pmatrix} 2 \\ 0 \\ 1 \end{pmatrix}
= 1 \times 2 + 2 \times 0 + 3 \times 1
= 5
$$

つまり、$a_1 \cdot b_1 = 5$ です。縦ベクトルを 2 本並べると、$a_1$ と $b_1$、$a_1$ と $b_2$ の 2 つの内積が、行列積 1 回で求まります。

$$
\begin{pmatrix} 1 & 2 & 3 \end{pmatrix}
\begin{pmatrix} 2 & 1 \\ 0 & 1 \\ 1 & 1 \end{pmatrix}
=
\begin{pmatrix} a_1 \cdot b_1 & a_1 \cdot b_2 \end{pmatrix}
=
\begin{pmatrix} 5 & 6 \end{pmatrix}
$$

さらに横ベクトルも 2 本並べると、$a_1, a_2$ と $b_1, b_2$ のすべての組み合わせ、4 つの内積が求まります。

$$
\begin{pmatrix} 1 & 2 & 3 \\ 1 & 0 & 2 \end{pmatrix}
\begin{pmatrix} 2 & 1 \\ 0 & 1 \\ 1 & 1 \end{pmatrix}
=
\begin{pmatrix}
a_1 \cdot b_1 & a_1 \cdot b_2 \\
a_2 \cdot b_1 & a_2 \cdot b_2
\end{pmatrix}
=
\begin{pmatrix} 5 & 6 \\ 4 & 3 \end{pmatrix}
$$

左の行列が `x`（ここでは 2 トークン分）、右の行列が `w_qkv`（ここでは 2 列）、結果が `qkv` に相当します。トークンが増えれば左の行が、列が増えれば右の列が増え、結果もそれぞれ増えます。以降の `@` も、ベクトルを並べた行列どうしの積として読みます。

### 設計の動機：なぜ Q, K, V に分けるのか？

入力ベクトルをそのまま使うと、検索する側と検索される側の役割を区別できません。異なる投影行列を用意することで、同じ単語でも「文脈を探しに行く時の表現」と「文脈のヒントを与える時の表現」を使い分けられるようになります。

## 3. スコア計算とスケーリング

検索エンジンにクエリを入力すると、各ページのインデックスとの一致度でランキングされるように、各トークンの Q（クエリ）をすべてのトークンの K（インデックス）に突き合わせて、関連度のスコア行列を作ります。この突き合わせには内積を使います。内積はベクトルが同じ方向を向いているほど値が大きくなるため、関連性の高いトークン同士ほどスコアが高くなります。

ただし、次元数が大きいと内積の値が非常に大きくなり、特定のトークンのスコアが過剰に高くなってしまいます。これを防ぐために、次元数 $\sqrt{d_k}$ で割ることでスケーリングします。

```python
# q: (head, seq_len, d_k), k: (head, seq_len, d_k)
# transpose で k の最後の2軸を入れ替え → (head, d_k, seq_len)
# q @ k^T: (head, seq_len, seq_len) → ヘッドごとに全トークン間のスコア行列
scores = q @ k.transpose(0, 2, 1) / math.sqrt(d_k)
```

`@` 演算子は最後の 2 軸で行列積を計算し、先頭の軸（head）は独立した行列積のインデックスです。ここでの `q @ k^T` は線形変換ではなく、各トークンのベクトル同士の内積を総当たりで一括計算しています。結果は変換されたベクトルではなく、スカラー値（スコア）の表になります。つまり全ヘッドのスコア行列を一括計算しています。

### 実装上の注意：`np.sqrt` ではなく `math.sqrt`

$\sqrt{d_k}$ の計算に `np.sqrt(d_k)` を使うと、速度が大きく落ちます。NumPy 2 では `np.sqrt` が `np.float64` 型のスカラーを返し、float32 の配列をそれで割ると、結果の配列が **float64 に格上げ**されるためです。格上げされた配列は以降の行列積もすべて float64 で行われ、float32 の重みとの演算では重みが毎回変換されます。

```python
x = np.ones(3, dtype=np.float32)
print((x / np.sqrt(64)).dtype)    # float64（np.float64 スカラーで割ると格上げされる）
print((x / math.sqrt(64)).dtype)  # float32（Python の float なら dtype は変わらない）
```

このリポジトリでは、Attention のスケーリングと GELU（👉[08](08_mlp.md)）の 2 か所を `math.sqrt` に変えただけで、100 トークンの生成が約 97 秒から約 30 秒（Ryzen 5 3400G、CPU）になりました。ロジットも float32 のままになります。NumPy 版と PyTorch 版の差が約 3 倍まで縮まったことからも、「遅いのはライブラリのせい」と決めつけず、dtype を確認する価値があります。

## 4. Softmax

スコアを確率分布に変換するため、各スコアの指数 `exp(x)` を取り、合計で割ることで全体の和が 1 になるよう正規化します。これを **Softmax** と呼びます。最もスコアが高い要素に高い確率が割り当てられ、スコアの差が大きいほど確率の偏りも大きくなります。

$$
\text{Softmax}(x_i) = \frac{\exp(x_i)}{\sum_j \exp(x_j)}
$$

※ 分母 $\sum_j \exp(x_j)$ は統計力学の分配関数に対応します。

単純に実装すると `np.exp(x) / np.sum(np.exp(x))` となりますが、`x` の値が大きいと `exp(x)` がオーバーフローしてしまうため、最大値を引くことで回避します。最大値を引いても分子・分母に同じ定数がかかるため、結果は変わりません。

また、`x` は複数のベクトルを含んでいるため、`axis` と `keepdims` を指定することで、正しい次元で計算できるようにします。（詳細は後述）

```python
def softmax(x):
    # 最大値を引いてからexp（数値安定化）
    exp_x = np.exp(x - np.max(x, axis=-1, keepdims=True))
    # 合計で割って確率分布に変換
    return exp_x / np.sum(exp_x, axis=-1, keepdims=True)
```

前節のスケーリングはこの Softmax の性質と密接に関係しています。スケーリングなしでスコアが大きくなりすぎると、Softmax の出力がほぼ one-hot（1箇所だけ 1 で他は 0）になり、他のトークンからの情報を取り込めなくなります。

### 補足：axis と keepdims の役割

2次元配列を例に動作を確認します。

```python
>>> a = np.array([[1, 2, 3],
...               [4, 5, 6]])
>>> a.shape
(2, 3)
```

`axis` は操作する軸を指定します。`axis=0` は行方向（縦）、`axis=1`（= `axis=-1`）は列方向（横）に集約します。

```python
>>> np.max(a, axis=0)          # 各列の最大値
array([4, 5, 6])               # shape: (3,)
>>> np.max(a, axis=1)          # 各行の最大値
array([3, 6])                  # shape: (2,)
```

`keepdims=True` を付けると、集約した軸が大きさ 1 の次元として残ります。これにより元の配列との引き算などでブロードキャスト（shape が異なる配列同士の演算で、大きさ 1 の軸を自動的に拡張して要素ごとに計算する仕組み）が正しく動きます。

```python
>>> m = np.max(a, axis=1, keepdims=True)
>>> m
array([[3],   # shape: (2, 1)
       [6]])
>>> a - m     # (2, 3) - (2, 1) → ブロードキャスト可能
array([[-2, -1,  0],
       [-2, -1,  0]])
```

`keepdims=False`（デフォルト）だと次元が潰れるため、ブロードキャストができなくなります。

```python
>>> m = np.max(a, axis=1)  # keepdims=False と同じ
>>> m
array([3, 6])  # shape: (2,)
>>> a - m
ValueError: shapes (2,3) and (2,) not aligned
```

## 5. 因果マスキング（Causal Masking）

GPT-2 では、Q と K による検索の対象は、自分自身と、文中で自分より文頭側にあるトークンだけです。つまり**後方参照**しかできません。参照の可否を図にすると、可能な範囲は下三角行列の形になります。4トークンの場合を示します。

|          | tok0 | tok1 | tok2 | tok3 |
|----------|------|------|------|------|
| **tok0** | OK   | NG   | NG   | NG   |
| **tok1** | OK   | OK   | NG   | NG   |
| **tok2** | OK   | OK   | OK   | NG   |
| **tok3** | OK   | OK   | OK   | OK   |

※ 「縦の見出し」から「横の見出し」を見た時の可否を表しています。例えば tok1 は tok0, tok1 を参照できますが、tok2, tok3 は参照できません。

文末側のトークンを参照できないのは、GPT-2 が「次の単語を予測する」モデルだからです。学習時には各位置で「次のトークン」を同時に予測するので、もし文末側のトークンが見えてしまうと、答えを見て予測することになります。また、推論時には文末側のトークンはまだ存在しません。学習時と推論時で条件を揃えるために、参照できない範囲を隠します。

各トークンが自分自身と過去のトークンだけを参照できるようにするには、未来のスコアを $-10^{10}$（実質 $-\infty$）で上書きし、Softmax 適用後の確率を 0 にします。`np.tril` で下三角行列を作り、参照不可範囲のスコアを書き換えます。

```python
# 下三角行列を生成（対角線と左下が1、右上が0）
mask = np.tril(np.ones((seq_len, seq_len)))
# mask が 0 の位置（未来）を -1e10 で上書き
scores = np.where(mask == 0, -1e10, scores)
# Softmax で確率に変換（-1e10 → ほぼ 0）
probs = softmax(scores)  # 注目度行列
```

入力 "The capital of France is" での注目度行列 `probs` から Head 0 の部分を抜粋します。

|          |     'The'|' capital'|     ' of'| ' France'|     ' is'|
|----------|---------:|---------:|---------:|---------:|---------:|
|     'The'|    1.0000|          |          |          |          |
|' capital'|    0.8464|    0.1536|          |          |          |
|     ' of'|    0.7014|    0.2237|    0.0749|          |          |
| ' France'|    0.6077|    0.1788|    0.1439|    0.0696|          |
|     ' is'|    0.6099|    0.1519|    0.0626|    0.0945|    0.0812|

最初のトークン 'The' は自分だけに 100% 注目し、最後のトークン ' is' はすべてのトークンを参照できます。このように最後のトークンに情報が集約されるのが因果マスキングの特徴です。

この表を列方向（注目される側）から読み直すと、情報は文頭側から文末側への一方向にしか伝わらないことが分かります。'The' の情報は後続のすべてのトークンに流れ込みますが、逆向きには流れません。その結果、全トークンを参照できる最後のトークンには、それ以前のすべてのトークンの情報が集まります。次の単語の予測に最終トークンの出力だけを使うのは、このためです（👉[10](10_output.md)）。

### 補足：Attention の種類と他のモデル

GPT-2 の Attention は、同じ系列内のトークン同士で注目し合うため **Self-Attention** と呼ばれます。因果マスキングにより未来を見ないようにしていますが、すべてのモデルがこの制約を持つわけではありません。

Transformer の原論文（Vaswani et al., 2017）は翻訳タスクを対象とし、**Encoder**（入力を双方向に参照して表現を作る）と **Decoder**（過去のみを参照して出力を生成する）の 2 つの部分から構成されています。Decoder には Self-Attention に加えて、Encoder の出力を参照する **Cross-Attention** もあります。Cross-Attention では Q が Decoder 側、K と V が Encoder 側から来ることで、「翻訳元のどの単語に注目するか」を決めます。

GPT-2 は Decoder のみの構成なので Self-Attention だけで動いています。一方 BERT（Devlin et al., 2019）は Encoder のみを使い、同じく Self-Attention ですが因果マスクなしで文全体を双方向に参照します。入力の一部のトークンを `[MASK]` に置き換え、その元の単語を当てる学習方式（Masked Language Model）を取ります。BERT は主に文章の理解（分類や質問応答）に使われますが、マスクした位置を繰り返し予測して埋めることで文章を生成する試みもあります。テキストの拡散モデルもこの系譜にあり、GPT のような左から右への逐次生成とは異なるアプローチです。

## 6. Value の重み付き平均

ここまでの処理で、各トークンが他のトークンにどれだけ注目すべきかの確率分布（probs）が得られました。この確率分布を重みとして、V（各トークンが持つ「実際の情報」）の加重平均を取ります。

```python
# probs: (head, seq_len, seq_len) — 各トークンの注目度分布
# v:     (head, seq_len, d_k)     — 各トークンの情報ベクトル
# out:   (head, seq_len, d_k)     — 文脈を反映した新しいベクトル
out = probs @ v
```

この行列積も、線形変換ではなく加重平均の一括計算です。probs の各行が確率分布（合計 1）なので、V の行ベクトルを確率に応じて混合した結果が得られます。

具体的に見るため、注目度行列 `probs` で ' is' の行を再掲します。

|     |     'The'|' capital'|     ' of'| ' France'|     ' is'|
|-----|---------:|---------:|---------:|---------:|---------:|
|' is'|    0.6099|    0.1519|    0.0626|    0.0945|    0.0812|

' is' の出力ベクトルは、各トークンの V をこの注目度で混合したものになります。'The' の V に 0.61、' capital' の V に 0.15 を掛けて足し合わせるというように、注目度の高いトークンほど多くの情報が流れ込みます。

実際の計算結果（Head 0、先頭 5 次元）：

```text
各トークンの V:
         'The': [-0.0131, -0.0145, +0.1269, -0.0221, -0.2082, ...]
    ' capital': [+0.0023, +0.1138, +0.1138, +0.3719, +0.1921, ...]
         ' of': [-0.0043, -0.1001, -0.0527, -0.0737, -0.0805, ...]
     ' France': [-0.1402, -0.0411, -0.2345, +0.1896, +0.0455, ...]
         ' is': [+0.2624, -0.2693, +0.3042, -0.1792, -0.1881, ...]

加重平均の結果（' is' の出力）:
         ' is': [+0.0002, -0.0235, +0.0939, +0.0418, -0.1138, ...]
```

たとえば先頭の次元では、各トークンの V の値に注目度を掛けて足し合わせることで、出力の +0.0002 が得られます。

```text
-0.0131 * 0.6099 = -0.0079692  ('The')
+0.0023 * 0.1519 = +0.0003562  (' capital')
-0.0043 * 0.0626 = -0.0002718  (' of')
-0.1402 * 0.0945 = -0.0132526  (' France')
+0.2624 * 0.0812 = +0.0213002  (' is')
                計 +0.0002
```

これが Attention の核心です。各トークンが、自分にとって重要な他のトークンから情報を集めて、文脈を反映した新しいベクトルを得ます。入力時は独立だったトークンのベクトルが、この処理を通じて互いの情報を取り込み、「文脈を理解した」表現に変わります。

## 7. Multi-Head の統合

ここまでの処理は全12ヘッドで同時に行われています。これまで Head 0 を例に見てきましたが、各ヘッドはそれぞれ異なる「注目パターン」を学習しています。

最後のトークン ' is' の注目先（上位3）：

| Head | 1位 | 2位 | 3位 |
|------|-----|-----|-----|
| Head 0 | 'The'(0.610) | ' capital'(0.152) | ' France'(0.094) |
| Head 1 | ' is'(0.978) | ' of'(0.015) | 'The'(0.003) |
| Head 2 | 'The'(0.469) | ' of'(0.209) | ' is'(0.181) |
| Head 3 | ' is'(0.798) | 'The'(0.106) | ' of'(0.067) |

Head 0 は 'The' や ' capital' など文の主要な単語に分散して注目し、Head 1 は自分自身に集中するなど、各ヘッドが異なる関係性を捉えています。

12 ヘッドすべてについて、最後のトークン ' is' が最も注目するトークンとその注目度を示します。

| Head | 最も注目するトークン | 注目度 |
|-----:|---------------------|-------:|
| 0 | 'The' | 0.61 |
| 1 | ' is' | 0.98 |
| 2 | 'The' | 0.47 |
| 3 | ' is' | 0.80 |
| 4 | ' is' | 0.27 |
| 5 | ' is' | 0.92 |
| 6 | ' France' | 0.35 |
| 7 | ' is' | 0.33 |
| 8 | ' is' | 0.47 |
| 9 | 'The' | 0.42 |
| 10 | 'The' | 0.40 |
| 11 | 'The' | 0.47 |

'The' に注目するヘッドが 5 つ（0, 2, 9, 10, 11）、' is' 自身に注目するヘッドが 6 つ（1, 3, 4, 5, 7, 8）、' France' に注目するヘッドが 1 つ（6）あります。このようにヘッドごとに注目先が異なり、それぞれ違う観点で情報を集めています。ここではブロック 0 の結果で、後ろのブロックでは文脈が取り込まれた入力になるため、注目の傾向は層によって異なります。

各ヘッドの結果（64 次元 × 12 ヘッド）を結合して元の 768 次元に戻し、出力射影行列を掛けます。

```python
# ヘッドの結合: (12, seq_len, 64) → (seq_len, 12, 64) → (seq_len, 768)
out = out.transpose(1, 0, 2).reshape(seq_len, embed_dim)
# 出力射影（アフィン変換）
return out @ self.w_out + self.b_out
```

この出力はまだ次のトークンを決定するものではありません。この後、残差接続と LayerNorm を経て MLP（フィードフォワード層）を通り、さらにこれを 12 層繰り返した最終出力から次のトークンが予測されるためです。

## まとめ

GPT-2 の Attention の処理は以下の流れで進みます。

1. 各トークンのベクトルから Q, K, V を生成し、ヘッドに分割する
2. Q と K の内積でスコアを計算する
3. 未来のトークンをマスクで遮断する
4. Softmax でスコアを確率分布に変換する
5. 確率に応じて V の加重平均を計算する
6. 全ヘッドの結果を結合し、出力射影を計算する
